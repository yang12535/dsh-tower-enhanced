## 已采用的实现约束（请挑战，但不要忽略）

1. `resume` 通过 direct parent 的 `subagents.sendMessage()` 触发宿主 `coldResume`，恢复原 child 的 Session、descriptor、provider/model/reasoningEffort、cwd 和 composition；不是保留 worktree 后新开一个失忆代理。
2. 新 Tower run 在发送恢复消息前持久化 WAL：previous runId、childId、sessionSeq、prompt SHA-256；prompt 原文不写入 Tower 状态。reviewer prompt 必须从本轮 `beginSpawn` 产生的新 base/tip binding 构造。
3. `subagent/start` / `subagent/end` 以本轮 hostRunId 绑定；message accepted 不等于完成。session 结果读取既使用 offset，也在下一条 `user/message` 截断，避免前后 epoch 的 output、diagnostic、verdict 串联。
4. coldResume 不恢复原 activation 的 outputSchema/maxTokens。恢复 reviewer 的完整回答必须是单个 JSON object 或单个 JSON fence，并通过 `REVIEW_OUTPUT_SCHEMA` 零违规校验；否则 `review_failed`，不得批准。
5. active run 必须拒绝 resume；陈旧 running 记录先 `recover`，不 adopt 旧进程。disposal、rollback、track 必须 exactly-once，旧 epoch 不得 interrupt 新 epoch。
6. 普通 spawn/send/recover、既有状态机、公开错误码和 merge gate 不应被改变。没有远程操作或 push。
